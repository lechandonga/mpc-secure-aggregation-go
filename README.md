# 多方安全计算组件：门限秘密共享与安全聚合（本地模拟）

纯 Go 实现，零第三方依赖。在单个进程内用多个本地“参与方”模拟真实协议交互，
覆盖门限秘密共享（Shamir）、安全聚合（加法份额求和）与安全乘法（Beaver 三元组），
并对参与方异常、预处理材料复用/耗尽、旧会话重放、并发会话给出确定性、可解释的结论。

素数域：`p = 2^64 - 2^32 + 1`（Goldilocks），所有数值运算均在 `F_p` 上。

## 目录结构

- `pkg/field`：素数域运算（加/减/乘/逆元/随机元素），值域校验。
- `pkg/shamir`：t-of-n 门限秘密共享，拆分即生成份额承诺，恢复前强制校验。
- `pkg/mpc`：本地参与方网络、会话状态机、预处理三元组材料库、安全求和/乘法协议。
- `cmd/demo`：可直接运行的端到端演示。

## 协议流程

### 1. 门限秘密共享（Shamir, t-of-n）

1. `Split(secret, n, t)`：在 `F_p` 上采样随机 `t-1` 次多项式，`f(0)=secret`，
   参与方 `i` 得到份额 `(i, f(i))`；同时用 `SHA-256` 为每份份额生成承诺标签（Verifier）。
2. `Reconstruct(shares, verifier)`：
   - 校验下标范围、份额属于 `F_p`、份额值与承诺匹配；
   - 合法且互不重复的份额数 `< t` → 拒绝；
   - 用 Lagrange 插值在 `x=0` 恢复秘密；
   - 提供超过门限份额时，额外校验所有份额落在同一条多项式上。

### 2. 安全聚合（输出 `Σ x_i`）

1. 每方把私有输入 `x_i` 切成 n 份加法份额，第 j 份发给第 j 个参与方（自己保留本地槽位）。
2. 每方把收到的份额与自留份额相加，得到输出的加法份额。
3. 各方把输出份额交给 leader，leader 求和并广播结果；follower 回 ACK，
   leader 收齐全部 ACK 后各方才提交（全有或全无）。

网络中只出现随机份额，任何单份份额在域上均匀分布，不泄露对应输入。

### 3. 安全乘法（输出 `(Σ x_i)·(Σ y_i)`，Beaver 三元组）

预处理阶段：可信本地经销商生成 `(a,b,c=ab)`，为每个参与方 `i` 准备
`(a_i,b_i,c_i)` 加法份额，其中 `c` 的份额相关构造以严格保证 `Σ c_i = ab`。

在线阶段（每会话消费且仅消费一份三元组）：

1. 与安全聚合相同地得到 `X=Σx`、`Y=Σy` 的本地份额 `X_i, Y_i`。
2. 每方计算掩码份额 `d_i = X_i - a_i`、`e_i = Y_i - b_i` 并互相交换，公开重构 `d, e`。
   由于 `a,b` 均匀随机，`d,e` 不泄露 `X,Y` 的任何信息。
3. 每方计算
   `z_i = c_i + d·b_i + e·a_i + d·e/n`，
   满足 `Σ z_i = c + db + ea + de = XY`；leader 聚合 `z_i` 得到最终乘积。

### 4. 会话与异常处理

- 所有协议消息带 `sessionID / op / stage`。会话在全体参与方上原子登记，
  登记失败则整体回滚，不产生任何协议消息或半初始化状态。
- 每阶段等待消息有独立截止时间；参与方崩溃（`CrashParty`）后：
  - 不再接收/发送消息；
  - 其余方等待超时或收到 ABORT 广播后确定性中止；
  - 没有任何一方提交部分结果，会话进入 aborted 终态。
- 重启（`RestartParty`）后崩溃标记解除，但历史会话表保留：
  - 已完成/中止的旧会话再次发起 → `ErrSessionStale`；
  - 从未登记过的会话收到消息 → `ErrSessionUnknown`。

### 5. 预处理材料的并发分配

- 集群持有全局原子三元组 ID 分配器；每方材料库通过 `ReserveID(session,id)`
  占用对应份额。因此多个会话并发时，同一会话在各方拿到的永远是同一组对齐份额。
- 材料占用是“两阶段”的：`ReserveID`（锁定）→ 协议成功 `Consume` / 失败 `Release`。
- 中止会话占用的材料**直接销毁、不回池**，杜绝任何复用可能。
- 同一 session 重复预留/消费 → `ErrMaterialReused`；池空 → `ErrMaterialExhausted`。

## 可区分错误（errors.Is）

| 错误哨兵 | 触发场景 |
| --- | --- |
| `shamir.ErrInvalidParams` | 门限/份额数非法、秘密不在域内、承诺为空 |
| `shamir.ErrInsufficientShares` | 合法份额数低于门限 |
| `shamir.ErrShareOutOfField` | 份额值不在 `F_p` |
| `shamir.ErrShareIndexInvalid` | 份额下标越界 |
| `shamir.ErrShareTampered` | 份额与承诺不匹配（篡改/张冠李戴） |
| `shamir.ErrSharesInconsistent` | 份额承诺有效但不落在同一多项式 |
| `mpc.ErrInvalidParams` / `ErrInvalidInput` | 集群参数 / 会话输入非法 |
| `mpc.ErrMaterialExhausted` | 三元组耗尽 |
| `mpc.ErrMaterialReused` | 三元组被二次预留/消费 |
| `mpc.ErrSessionUnknown` | 重启后出现从未登记的会话 |
| `mpc.ErrSessionStale` | 已结束/中止会话被重放 |
| `mpc.ErrPartyAborted` / `ErrStageTimeout` / `ErrProtocolAbort` | 参与方崩溃、等待超时、收到中止广播 |
| `mpc.ErrInconsistentView` | 消息阶段/来源与会话视图不符 |

## 威胁假设

- **半诚实参与方**：参与方按协议执行，但会尝试从收到的份额推断他人输入。
  加法份额与 Beaver 掩码保证单条消息在域上均匀随机；除协议最终输出外不泄露信息。
- **崩溃-中止（crash-abort）**：不保证公平性/活跃性；任何一方离线即整体中止，
  但保证不会输出错误结果或部分更新。
- **份额完整性**：Shamir 恢复依赖份额承诺识别篡改；在线协议中错误阶段/
  错误会话/错误来源的消息都会被拒绝。
- **预处理信任假设**：三元组由本地“可信经销商”生成并对齐 ID 分发。
  真实分布式部署中应替换为参与方联合生成（如基于加性秘密分享的离线协议）。
- **不在防御范围**：网络层在本地进程内是可靠、有序、即时的；不模拟流量分析、
  侧信道，也不防御恶意参与方伪造虚假（但承诺合法）的在线协议消息。

## 验证方法

```bash
# 全部单元测试（-v 日志可看到每个业务及其用例的开始/通过与拒绝原因）
go test -count=1 -v ./...

# 竞态检测（需要 cgo）
CGO_ENABLED=1 go test -race -count=1 ./...

# 端到端演示
go run ./cmd/demo
```

测试按业务组织，日志形如 `业务[材料复用] 用例[同会话重复预留/消费被拒绝] 通过`，
覆盖业务：

- 门限秘密共享：参数非法、门限恢复、份额不足、份额篡改（值/下标/冒用/集合不一致）；
- 安全聚合：正确性与交互记录无明文输入、输入/参数非法；
- 安全乘法：Beaver 正确性与扣减、材料耗尽、材料复用、中止后不回池；
- 中途退出：开局崩溃零消息、中途崩溃全体中止无部分结果；
- 旧会话拒绝：完成后重放、重启后迟到消息、未知会话；
- 并发会话：8 会话并发各扣 1 份结果独立且恰好清零、抢材料时恰好一份被耗尽拒绝。
